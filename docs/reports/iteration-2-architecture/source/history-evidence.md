## AI provider evolution and wording limits

The original ERD at `ff57c98:docs/iteration1_erd.md:9-11` proposed NLP then AI for added-task exposure and skill matching. The reachable Iteration 1 milestone changes exposure matching to TF-IDF with `insufficient_data`, not an assumed LLM fallback. Cite `3801a0a:docs/iteration1_erd.md:9-10` and its later explanation at the end of the business model section.

Verified provider milestones from the history of `backend/app/services/ai_gateway.py` are:

- `b610848`, 7 September 2026 at 23:42:02, adds candidate-constrained backend APIs.
- `7401097`, 10 September 2026 at 14:48:44, wires an optional LLM provider and score context.
- `39bf3d6`, 10 September 2026 at 16:25:48, adds Responses API and keyless relay support.
- `ba2e3d1`, 10 September 2026 at 16:52:47, adds configured-primary plus OpenCode fallback routing.
- `36b2a09`, 16 September 2026 at 06:23:01, adds learning progress, calendar and daily brief functionality.
- `6f5bc67`, 17 September 2026 at 03:02:21, adds one-shot task-assistance controls.

The current source does **not** mean 'no API key equals offline AI'. `aa4f8fb:backend/app/core/config.py:68-77` enables the fallback by default. `backend/app/services/ai_gateway.py:792-863` builds a configured primary when a key or explicit keyless mode exists, builds a keyless OpenCode fallback when enabled, and uses deterministic-only behavior only when neither provider can be built. Do not claim this external relay is currently reachable or produces valid output without testing it.

There is also a separate skill-direction provider using `SKILL_LLM_*`. See `aa4f8fb:backend/app/core/config.py:48-55` and `backend/app/services/skill_directions.py:73-133`. It has its own missing-key guard and HTTP call. Do not describe every AI feature as one provider path.

The gateway contains schema validation, candidate constraints, retries and fallback logic in source. Cite `aa4f8fb:backend/app/services/ai_gateway.py:70-145,148-183,577-593`. Those are implementation mechanisms, not a blanket claim that all AI output is always correct or that all current AI tests pass. The parent review has reported nine baseline backend test failures, so a report must keep those failures and the lack of live provider verification explicit.

## Report-ready conclusion

The main design stayed a React frontend, a FastAPI backend and an external PostgreSQL database. The larger changes were how user work is stored, how shared frontend behavior is owned, how optional AI providers are selected and how the application is started and checked. The latest change keeps page-based UI and extracts only shared state operations. Its practical aim is to preserve saved work and make account and module boundaries easier to verify. This conclusion follows the code changes. It does not assume why individual team members chose earlier layouts.
